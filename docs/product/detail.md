# Moon Aura — 세부 설계 및 결정 관리 (Detail)

> **이 문서는 수시로 업데이트한다.** 상위 정책은 [`service-plan.md`](service-plan-final.md)를 따른다. 아래 항목은 최초 정리한 세부 설계와 앞으로 결정할 사항이다. 변경할 때는 **관련 항목만 갱신**하고 중요한 변경은 맨 아래 이력에 남긴다.

## 1. 현재 확정한 세부 방향

### 1-1. 인트로
- **[확정]** 후킹 문구: **“태어난 순간에 담긴, 여덟 글자의 이야기.”**
- **[확정]** 짧은 인트로에서 사주 입력 화면으로 자연스럽게 이어진다.
- **[확정]** 건너뛰기 제공, 재방문 시 반복 강제하지 않음.
- **[검토 중]** 인트로 지속시간 2~3초, 문구 이동/페이드 효과, 최초 방문 판별 방법.

### 1-2. 메인 입력 화면
- **[확정]** 긴 소개 화면 대신 첫 화면에 입력 폼을 배치한다.
- **[검토 중]** 데스크톱 왼쪽 설명 40% / 오른쪽 입력 카드 60%.
- **[검토 중]** 모바일: 로고 → 짧은 문구 → 입력 카드.
- **[검토 중]** 입력 항목: 양력/음력, 음력 윤달 여부, 생년월일, 출생 시간(모름 포함), 성별, 출생 지역(선택), 관심 주제(선택 또는 결과 후).
- **[검토 중]** CTA: “내 사주 분석 시작하기”.

### 1-3. 결과 및 상담
- **[확정]** 종합 풀이 + 올해 운세 + 제한적 추가 질문이 MVP 핵심이다.
- **[검토 중]** 결과 배열: 핵심 요약 → 올해 운세 → 사주 여덟 글자·오행 → 상세 풀이 → 실천 조언 → AI 상담.
- **[검토 중]** 오행 차트 방식, 결과 카드 레이아웃, 저장/공유 처리, 질문 칩 문구.
- **[확정]** 출생 시간이 없을 경우 시주를 확정적으로 표시하지 않는다.

### 1-4. 디자인 토큰 초안
- **[확정 방향]** 구조감 있는 카드형 UI와 부드러운 라벤더 계열 감성의 결합.
- **[검토 중]** Navy `#525A6B`, Lavender `#9B8CFF`, Lilac `#C8B8FF`, Ivory `#F8F5F1`, White `#FFFFFF`.
- **[검토 중]** 제목: MaruBuri 등 세리프 / 본문: Pretendard 또는 SUIT.
- **[검토 중]** 카드 16~24px, 버튼 12~16px 라운드, 180~300ms 수준의 미세 인터랙션.

### 5-1. 인트로 UX — The Beginning

- **날짜:** 2026-10-11
- **변경 내용:** 후킹 문구가 위로 이동하면서 사주 입력 카드가 등장하는 인트로 A안 채택
- **상태:** 확정 (구현 전)

#### 핵심 문구
"태어난 순간에 담긴, 여덟 글자의 이야기."

#### 애니메이션 연출
1. **0.0~0.6초:** 웜 아이보리 배경 중앙에 세리프 문구가 페이드 인된다.
2. **0.6~1.4초:** 문구를 중앙에 유지하며 라벤더 색상의 원형 장식이 은은하게 움직인다.
3. **1.4~2.1초:** 문구가 화면 상단으로 이동하면서 자연스럽게 축소된다.
4. **1.8~2.6초:** 사주 입력 카드가 아래에서 위로 올라오며 페이드 인된다.
5. **2.6초 이후:** 사주 정보를 즉시 입력할 수 있는 메인 화면이 완성된다.

#### 디자인 규칙
- 배경: Warm Ivory `#F8F5F1`
- 메인 문구: MaruBuri SemiBold
- 텍스트: Deep Charcoal `#292B35`
- 포인트: Soft Lavender `#9B8CFF`
- 장식: 얇은 원형 궤도와 여덟 개의 점
- 입력 카드: 화이트 배경, 20px 라운드, 은은한 그림자

#### UX 필수 조건
- 첫 방문 시 인트로 자동 실행
- 인트로 건너뛰기 기능 제공
- 재방문 시 자동 인트로 생략
- 사용자 상호작용 시 즉시 입력 화면으로 전환 가능
- 모바일에서는 문구 크기와 이동 거리 최적화
- 모션 감소 설정 시 애니메이션 없이 입력 화면 표시
- 인트로 종료 후 페이지 이동 없이 사주 입력 진행

#### 주의 사항
- 인트로 때문에 실제 기능 이용이 지연되지 않도록 한다.
- 긴 서비스 소개 화면은 추가하지 않는다.
- 화면 전환 과정에서 레이아웃이 튀거나 흔들리지 않도록 한다.
- 사주 입력 기능은 인트로 애니메이션과 독립적으로 작동해야 한다.

### 5-2. 사주 입력 화면 — 한 화면 입력형

- **날짜:** 2026-10-11
- **변경 내용:** 사주 입력 화면을 단계별 입력 방식이 아닌 한 화면 입력 방식(A안)으로 확정
- **상태:** 확정 (구현 전)

#### 핵심 설계 방향
- 인트로(5-1)가 종료되면 같은 화면에 사주 입력 카드가 나타난다.
- 사용자는 별도의 페이지 이동 없이 모든 필수 정보를 입력할 수 있다.
- 입력 과정에서 불필요한 단계 전환이나 '다음' 버튼을 사용하지 않는다.
- 모바일에서도 직관적이고 간결한 입력 경험을 제공한다.

#### 입력 항목
1. 양력 / 음력 선택
2. 생년월일 입력
3. 음력 선택 시 평달 / 윤달 선택
4. 태어난 시간 선택
5. 태어난 시간 모름 옵션
6. 성별 선택
7. 출생 지역(선택 사항)

#### UI 디자인
- 화이트 배경의 단일 입력 카드
- 카드 모서리 반경 20px
- 양력/음력 및 성별은 선택형 버튼 사용
- 생년월일은 날짜 선택 및 직접 입력 지원
- 태어난 시간은 드롭다운 또는 선택형 UI
- 선택된 항목은 라벤더 색상으로 강조
- 주요 버튼은 카드 하단에 배치

#### CTA 버튼
**"내 사주 분석 시작하기 →"**

- 필수 입력값 확인 후 분석 시작
- 입력 오류 발생 시 해당 항목에 안내 표시
- 정상 입력 시 결과 화면으로 이동

#### 모바일 UX
- 단일 열 레이아웃 적용
- 좌우 여백 약 20px
- 입력 영역과 버튼은 터치하기 충분한 크기로 구성
- 불필요한 장식 최소화
- 짧은 스크롤만으로 입력 완료 가능

#### 주의 사항
- 사주 입력을 여러 페이지로 분리하지 않는다.
- 필수 입력 항목 외에는 과도한 정보를 요구하지 않는다.
- 태어난 시간을 모르는 사용자도 분석할 수 있도록 한다.
- 입력한 정보는 분석 화면으로 정상 전달되어야 한다.
- 개인정보는 기존 서비스 기획서의 저장 정책을 따른다.

### 5-3. 사주 분석 결과 화면

- **날짜:** 2026-10-11
- **변경 내용:** 결과 표시 순서 A안, 오행 가로 막대그래프 A안, 핵심 요약 후 상세 펼침 A안 채택
- **상태:** 확정 (구현 전)

#### 결과 화면 구성
1. 핵심 성향 요약
2. 올해의 운세
3. 오행 분포 및 사주팔자
4. 상세 해석 및 실천 조언
5. AI 추가 상담 연결

#### UI 및 시각화
- 핵심 성향을 가장 먼저 보여준다.
- 올해 운세를 두 번째 주요 카드로 배치한다.
- 오행(목·화·토·금·수)은 5개의 가로 막대그래프로 표현한다.
- 오행별 수치와 명칭을 함께 표시한다.
- 사주팔자는 년주·월주·일주·시주를 카드 또는 표 형태로 구성한다.
- 실제 계산 결과를 사용하며 임의의 분석값을 생성하지 않는다.
- 모바일에서는 카드형 세로 레이아웃을 적용한다.

#### 해석 방식
- 처음에는 핵심 요약을 간결하게 보여준다.
- 상세 설명은 펼치기/접기 기능으로 제공한다.
- 장점과 보완점을 균형 있게 설명한다.
- 결과의 마지막에는 실천 가능한 조언을 제공한다.
- 결과 카드에는 이미지 저장 및 공유 기능을 제공한다.

### 5-4. AI 상담 화면

- **날짜:** 2026-10-11
- **변경 내용:** 일반 메신저 말풍선 B안, 추천 질문과 자유 입력 B안, 핵심 결론·이유·실천 조언 A안 채택
- **상태:** 확정 (구현 전)

#### UI 구성
- 일반적인 메신저 형태의 말풍선 UI를 사용한다.
- 사용자 질문과 AI 답변을 시각적으로 구분한다.
- 하단에 메시지 입력창과 전송 버튼을 배치한다.
- AI 답변 생성 중에는 로딩 상태를 표시한다.
- 모바일 키보드가 나타나도 입력창을 편리하게 사용할 수 있어야 한다.

#### 질문 방식
- 추천 질문 버튼과 자유 입력을 모두 제공한다.
- 추천 질문을 선택하면 해당 질문을 바로 전송할 수 있다.
- 사용자는 직접 원하는 내용을 질문할 수 있다.
- 서비스 운영 비용에 따라 이용량 제한을 적용할 수 있도록 설계한다.
- 구체적인 질문 횟수 제한은 추후 결정한다.

#### AI 답변 구조
1. 핵심 결론
2. 명리학적 해석 이유
3. 실천 가능한 조언

#### 해석 톤
- 따뜻하지만 분석적인 말투를 사용한다.
- 불필요하게 장황한 답변은 피한다.
- 단정적인 미래 예언을 하지 않는다.
- 기존 사주 계산 결과를 바탕으로 답변한다.
- 의료·투자·법률적 판단을 대신하지 않는다.

### 5-5. 브랜드 디자인 세부사항

- **날짜:** 2026-10-11
- **변경 내용:** 달의 궤도와 8개 점 A안, 아이보리·화이트 중심 컬러 A안, 제한적 세리프 사용 A안 채택
- **상태:** 확정 (구현 전)

#### 브랜드 상징
- 달의 궤도와 8개의 점을 핵심 시각적 상징으로 사용한다.
- 8개의 점은 사주팔자의 여덟 글자를 상징한다.
- 원형 궤도와 곡선을 활용해 부드럽고 신비로운 분위기를 표현한다.
- 과도한 별자리, 무속적 문양, 복잡한 장식은 사용하지 않는다.

#### 컬러 시스템
- 메인 배경: Warm Ivory `#F8F5F1`
- 카드 배경: White `#FFFFFF`
- 주요 텍스트: Deep Charcoal `#292B35`
- 보조 텍스트: `#77758A`
- 포인트: Soft Lavender `#9B8CFF`
- 그라데이션: `#9B8CFF` → `#C8B8FF`
- 보조 네이비: `#525A6B`
- 제한적 장식 색상: Muted Gold `#B9A06E`

아이보리와 화이트를 중심으로 구성하고, 라벤더는 버튼과 선택 상태 등 강조가 필요한 곳에 사용한다.

#### 타이포그래피
- 인트로 문구: MaruBuri SemiBold
- 메인 제목: MaruBuri 계열
- 결과 핵심 문구: MaruBuri 계열
- 본문: Pretendard
- 입력창 및 버튼: Pretendard
- AI 상담 메시지: Pretendard

세리프 글꼴은 인트로, 메인 제목, 결과 핵심 문구에만 제한적으로 사용한다.

#### 컴포넌트 스타일
- 카드 모서리 반경: 16~24px
- 버튼 모서리 반경: 12~16px
- 은은한 그림자 사용
- 둥근 선택 버튼과 입력창
- 명확한 정보 구분과 충분한 여백 유지
- 모바일 우선 반응형 디자인 적용

### 5-6. 명리학 해석 기준

- **날짜:** 2026-10-11
- **변경 내용:** 사주팔자·오행·십신·일간 중심 해석 A안, 결과별 불확실성 안내 A안 채택
- **상태:** 기본 해석 범위 확정 (세부 판단 규칙 추후 구체화)

#### 초기 해석 범위
초기 서비스에서는 다음 항목을 중심으로 해석한다.

1. 사주팔자
2. 오행 분포
3. 십신
4. 일간 중심의 성향
5. 올해의 운세

#### 해석 원칙
- 전통 명리학의 기본 개념을 활용한다.
- 복잡한 신강신약, 용신 등의 판단은 충분한 검토 후 확장한다.
- 명리학 전문 용어를 사용하더라도 일반인이 이해할 수 있도록 설명한다.
- AI는 계산 엔진이 제공한 결과를 기반으로 해석한다.
- 계산 결과에 없는 사실을 임의로 만들어내지 않는다.
- 해석은 따뜻한 분석형 말투를 유지한다.

#### 불확실성 안내
- 결과 화면에 사주 해석의 참고적 성격을 간단하게 안내한다.
- 불확실하거나 계산이 제한된 항목에는 개별적으로 안내한다.
- 태어난 시간을 모르는 경우 시주가 확정되지 않았음을 표시한다.
- 미래 사건이나 건강 문제 등을 확정적으로 예언하지 않는다.

### 5-7. 사주 계산 엔진

- **날짜:** 2026-10-11
- **변경 내용:** `saju-fortune` 우선 채택, 별도 사전 비교 검증 생략, 출생 시간 미상 시 제한적 풀이 A안 채택
- **상태:** MVP 채택 확정

#### 계산 엔진
- 초기 사주 계산 엔진으로 `saju-fortune`을 채택한다.
- 여러 계산 엔진을 사전에 비교하는 절차는 진행하지 않는다.
- 별도의 사전 정확도 검증 단계를 출시 차단 조건에 포함하지 않는다.
- 실제 구현 과정에서 오류나 호환성 문제가 확인되면 대안을 검토한다.
- 계산 엔진은 서버에서 실행한다.
- AI가 직접 사주팔자를 임의 계산하지 않도록 한다.

#### 출생 시간 미상 처리
- 태어난 시간을 모르는 사용자도 사주 분석을 진행할 수 있도록 한다.
- 시주는 '미확정'으로 표시한다.
- 연주·월주·일주 중심으로 제한적인 풀이를 제공한다.
- 태어난 시간을 임의로 설정하여 시주를 확정하지 않는다.
- 출생 시간 누락으로 인해 분석할 수 없는 항목은 명확하게 안내한다.

#### 구현 시 주의 사항
- 양력·음력 및 윤달 입력을 지원해야 한다.
- 계산 오류 발생 시 사용자에게 오류 상태를 안내한다.
- 계산에 실패한 경우 임의의 결과를 제공하지 않는다.
- 외부 패키지의 라이선스, 보안 및 호환성 문제는 실제 적용 시 확인한다.

### 5-8. 개인정보 및 기록 관리

- **날짜:** 2026-10-11
- **변경 내용:** 서버 영구 저장 없음 A안, 핵심 성향·키워드 중심 개인정보 제외 공유 A안 채택
- **상태:** 기본 개인정보 처리 방향 확정 (구현 전)

#### 개인정보 처리
- 생년월일시 및 출생 지역은 사주 분석 목적으로 사용한다.
- 초기 서비스에서는 사용자 개인정보를 서버에 영구 저장하지 않는다.
- 분석에 필요한 기간에만 데이터를 처리한다.
- 영구 저장하지 않는 정책에 맞춰 로그 및 임시 데이터 관리 방식을 설계한다.
- 개인정보 처리방침에 실제 데이터 처리 방식을 명확하게 안내한다.

#### 결과 저장
- 사용자가 직접 결과를 이미지 형태로 저장할 수 있도록 한다.
- 저장된 결과는 기본적으로 사용자의 기기에서 관리한다.
- 초기 서비스에서는 계정 생성 및 서버 기반 상담 기록 보관 기능을 제공하지 않는다.
- 새로 방문한 사용자는 필요 시 사주 정보를 다시 입력한다.

#### 결과 공유
공유 카드에는 다음 정보만 포함한다.

- Moon Aura 로고
- 핵심 성향
- 주요 키워드
- 짧은 해석 문구
- 브랜드 장식 요소

공유 카드에서 다음 정보는 제외한다.

- 생년월일
- 태어난 시간
- 출생 지역
- 기타 개인을 식별할 수 있는 정보

#### UX 원칙
- 결과 저장 및 공유 버튼을 직관적으로 배치한다.
- 개인정보가 공유 이미지에 실수로 포함되지 않도록 한다.
- 공유 전 미리보기를 제공한다.
- 저장 기능과 서버 기록 보관 기능을 구분한다.

## 6. 개발 계획

> **상태: [검토 중]** 아래 순서는 현재 코드와 문서에서 확인한 선행 조건을 반영한 제안이다. 상위 범위는 변경하지 않는다. 각 단계의 완료 조건을 통과한 뒤 다음 단계로 진행한다.

### 6-1. 현재 구현 상태
- 입력 폼, `POST /api/saju`, 입력 검증, `saju-fortune` 어댑터, Gemini 프롬프트·호출, 계산 결과 표시의 기본 골격이 있다.
- 계산 엔진 경계 검증은 미완료다. 테스트는 2025년 입춘 경계에서 패키지 결과가 기준과 다름을 확인하며, API는 검증 플래그가 켜지지 않으면 분석을 차단한다.
- 음력 입력은 실제 변환이 연결되지 않아 API에서 거절한다. 결과 화면의 AI 추가 질문, 결과 저장·공유도 구현되지 않았다.
- 현재 화면은 입력보다 소개 섹션이 먼저 나온다. 한 화면 입력 원칙과 인트로 동작은 아직 반영되지 않았다.

### 6-2. 단계별 진행 순서

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 0. 기준 문서와 결정 정리 | 상위 기획과 세부 설계의 엔진 상태 충돌을 사용자 결정으로 정리한다. 문서의 실제 파일명·링크를 현 구조와 일치시키고, 누락된 계산 엔진 명세를 작성하거나 링크를 제거한다. | 엔진 채택 여부와 정확도 기준이 문서에 일관되게 기록되고 잘못된 문서 링크가 없다. |
| 1. 계산 엔진 검증 및 선택 | `saju-fortune` 결과를 독립적으로 확인한 기준 사례와 대조한다. 입춘·월주 절기 경계, 날짜 경계, 출생 시간 미상, 시간대 및 출생지 처리, 지원할 경우 음력·윤달을 검증한다. 통과하지 못하면 대체 엔진 또는 보정 가능한 구조를 평가한다. | 경계 사례를 포함한 회귀 테스트가 기대값과 일치하고, 미지원 입력·계산 한계가 명확하다. 통과 전까지 운영 분석을 활성화하지 않는다. |
| 2. API·입력·개인정보 경계 | 실제 날짜 유효성, 필드 조합과 요청 오류를 검증하고, 미지원 음력은 계속 명확히 거절한다. 로그에 생년월일시·출생 지역·API 키가 남지 않는지 확인한다. 환경변수 예시의 검증 플래그 기본값도 비활성 상태로 둔다. | 잘못된 입력은 안전한 4xx 응답, 계산·외부 API 장애는 개인정보 없는 오류 응답을 반환한다. DB나 서버 영구 저장이 없다. |
| 3. AI 해석 품질 | 엔진이 제공하는 값만 프롬프트에 전달하고, 시간 미상·계산 한계·올해 운세를 구분한다. 모델 설정을 명시적으로 고르고, 키 누락·제공자 오류·빈 응답을 처리한다. 반복 생성으로 근거성·안전 문구·톤을 확인한다. | 계산값을 바꾸거나 없는 정보를 단정하는 답변을 막고, AI 생성 여부와 실패 상태가 UI에 정확히 표시된다. |
| 4. 핵심 입력·결과 UX | 확정된 한 화면 입력과 건너뛸 수 있는 인트로를 구현하고, 모바일 우선으로 검증한다. 결과는 핵심 요약 → 올해 흐름 → 팔자·오행 → 상세 풀이·실천 조언 순서로 구성하고 시주 미상을 분명히 표시한다. | 모바일과 데스크톱에서 입력·오류·로딩·결과 상태가 완결되고, 계산 결과만으로도 해석 한계가 보인다. 모션 감소 설정과 재방문 인트로 생략을 지원한다. |
| 5. 제한적 AI 추가 질문 | 결과를 근거로 하는 주제별 추천 질문과 자유 입력을 제공한다. 대화 맥락은 요청에 필요한 최소 정보만 사용하고 서버에 저장하지 않는다. 이용 제한 및 외부 API 장애 상태를 처리한다. | 종합 풀이와 올해 운세 흐름에서 추가 질문이 가능하고, 허용 주제·응답 형식·오류 동작이 테스트된다. |
| 6. 저장·공유 및 출시 점검 | 민감정보를 제외한 결과 이미지 저장·공유와 공유 전 미리보기를 구현한다. 접근성, 키보드·터치 사용성, 모바일 화면, 개인정보 안내, 배포 환경 변수를 점검한다. | 공유물에 생년월일시·지역이 포함되지 않고, 주요 사용자 흐름 및 운영 설정이 배포 환경에서 확인된다. |

### 6-3. 우선순위와 범위 통제
- **가장 먼저 진행할 일:** 0단계에서 엔진 결정의 문서 충돌을 해결한 뒤, 1단계의 기준 사례 검증을 완료한다. 현재 테스트가 입춘 경계 오차를 확인하므로 이 검증이 분석 기능 활성화의 출시 차단 조건이다.
- **기능 구현 순서:** 검증된 계산 → API·개인정보 경계 → AI 해석 → 입력·결과 UX → 추가 질문 → 저장·공유 및 배포 점검.
- 음력·윤달은 변환 정확도를 검증하기 전까지 지원한다고 표시하거나 분석에 사용하지 않는다. 출생지·진태양시 보정도 실제 지원 여부가 확인될 때까지 보장하지 않는다.
- DB, 계정, 결제, 궁합, 오늘의 운세, 대운 전용 기능은 이번 계획에 포함하지 않는다.

### 6-4. 완료 기준
- 계산 엔진 테스트와 입력 검증 테스트를 통과하고, 지원하지 않는 계산은 사용자에게 명확히 안내한다.
- 서버 키가 클라이언트에 노출되지 않으며, 생년월일시와 상담 내용이 서버에 영구 저장되거나 일반 로그에 기록되지 않는다.
- 로딩·성공·검증 실패·엔진 실패·AI 실패 상태를 주요 화면에서 확인할 수 있다.
- MVP 범위인 종합 풀이, 올해 운세, 제한적 추가 질문이 모바일과 데스크톱에서 동작한다.
- 테스트 및 프로덕션 빌드가 통과하고, 배포 환경에서 실제 요청 흐름을 점검한다.

### 6-5. 계획 수립 시 확인된 문서 충돌
- 상위 기획은 엔진을 검토 후보로 두고 검증 후 채택하도록 하지만, 이 문서의 5-7은 검증 생략 및 우선 채택으로 기록되어 있다. 상위 원칙 변경으로 처리하지 않고 엔진 결정 전 확인 항목으로 둔다.
- `docs/README.md`와 문서 간 링크에는 현재 저장소에 없는 파일명(`service-plan.md`, `saju-engine.md`)이 포함되어 있다. 0단계에서 실제 문서 구조에 맞춰 정리한다.
